# River Data Platform UI

The standalone, river-first web application for [River Data Platform](https://github.com/tclare95/river-data-platform).

This repository is the **UI/application layer**. RDP remains the source of measurement identity, observations, rainfall, CSO events and river-network data.

## Develop

Requires Node.js 22.13 or newer; CI and deployment use the Active LTS in `.nvmrc` (24).

```bash
npm ci
npm run dev
```

Open http://localhost:3000.

```bash
npm run check         # lint, format check, typecheck, tests and production build
npm run lint
npm run format        # or format:check
npm run typecheck     # next typegen && tsc --noEmit
npm run test          # or test:watch
npm run build
```

Install with `npm ci` and commit `package-lock.json` whenever dependencies change. `next-env.d.ts`
is generated by `next typegen`/`next build` and is not committed.

`npm run check` also runs `check:bundle`, which fails if AWS/RDP server material reaches browser assets.

## Data modes

`RDP_DATA_MODE` (server-only) selects where data comes from. See [.env.example](.env.example).

- **`fixture`** (default locally): synthetic responses in RDP's exact wire shapes, using real published IDs. The page says _sample data_; values are not observations. Refused on Vercel Production.
- **`live`**: signed reads of the RDP read API via Vercel OIDC → STS → SigV4, using RDP-UI's own stage role. Works only in Vercel Preview (staging) and Production (production); development tokens are rejected by the role trust, so there is no local live mode.

The adapter is in `src/lib/rdp/` (see [architecture](docs/ARCHITECTURE.md#rdp-adapter)).

## Deployment

Import this repository into Vercel as a **Next.js** project. No framework-specific configuration is needed for the shell; set the project's Node.js version to 24.x to match `.nvmrc`. This shell is safe to deploy without RDP credentials.

Live data **requires separate, approved setup** in RDP: a dedicated per-stage `river-data-platform-<stage>-ui-vercel-<environment>` role and a read handler that admits it. Do not reuse isHPPOpen's role. See [deployment configuration](docs/ARCHITECTURE.md#deployment-configuration).
